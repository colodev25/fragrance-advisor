# API

## Overview

The backend API is implemented using FastAPI and is located in:

```text
src/main.py
```

The API provides the communication layer between the website frontend and the `FragranceAdvisor`.

The general architecture is:

```text
Browser
   │
   │ HTTP
   ▼
FastAPI
   │
   ▼
FragranceAdvisor
   │
   ├── Search Engine
   └── LLM
   │
   ▼
Response
   │
   ▼
Browser
```

---

## Base URL

During local development, the frontend communicates with the backend through:

```text
http://127.0.0.1:8000
```

The current frontend sends chat requests to:

```text
POST /chat
```

---

## Endpoints

### `GET /`

Provides a basic endpoint that can be used to verify that the backend is running.

Conceptually:

```text
GET /
    ↓
FastAPI
    ↓
Health response
```

---

### `POST /chat`

Main endpoint used for conversational interaction.

The frontend sends a JSON request containing the user's message and session information.

The request model includes the following fields:

| Field           | Purpose                                           |
| --------------- | ------------------------------------------------- |
| `message`       | User's current message                            |
| `session_id`    | Identifier of the current conversation            |
| `max_price`     | Optional maximum price constraint                 |
| `step_override` | Optional override of the current guided-flow step |

The request is processed by the `FragranceAdvisor`.

Conceptually:

```text
POST /chat
      │
      ▼
ChatRequest
      │
      ▼
FragranceAdvisor.advise()
      │
      ▼
Advisor response
      │
      ▼
JSON response
```

The endpoint `/chat/` is also supported by the current implementation.

---

## Request Example

A simplified request can be represented as:

```json
{
  "message": "Cerco un profumo fresco e legnoso",
  "session_id": "sess_example"
}
```

Optional parameters can be added when required:

```json
{
  "message": "Qualcosa di simile ma sotto i 100 euro",
  "session_id": "sess_example",
  "max_price": 100
}
```

---

## Session Identifier

The `session_id` identifies the conversation associated with the request.

The frontend generates and stores the identifier locally using browser `sessionStorage`.

The same identifier is then sent with subsequent chat requests.

This allows the backend to associate multiple requests with the same conversation.

---

## Response

The response is generated by the advisor layer after processing the user's request.

The response can contain conversational information and product-related information used by the frontend to render the assistant message and any associated product actions.

The exact response structure is defined by the current implementation of `main.py` and the advisor response model.

---

## CORS

The API currently uses a permissive CORS configuration.

The current development configuration allows requests from arbitrary origins, methods and headers.

This is useful during local development and integration testing, particularly while the frontend and backend may be served from different origins.

For a production deployment, the allowed origins should be restricted to the actual website domains.

---

## Error Handling

The API layer is responsible for validating incoming requests before passing them to the advisor.

Errors occurring during request processing are handled at the backend level and returned as HTTP responses.

The advisor itself contains the application-specific logic required to process conversational requests.

---

## Frontend Integration

The current `index.html` communicates directly with the FastAPI backend.

The simplified integration is:

```text
index.html
     │
     │ fetch()
     ▼
POST /chat
     │
     ▼
FastAPI
     │
     ▼
FragranceAdvisor
     │
     ▼
JSON
     │
     ▼
JavaScript
     │
     ▼
Chat UI
```

The backend therefore remains independent from the visual presentation of the chat.

---

## Local Development

A typical local development environment consists of:

```text
Frontend
    ↓
index.html

Backend
    ↓
FastAPI
    ↓
127.0.0.1:8000
```

The frontend must be configured to use the address where the FastAPI application is running.

Environment variables required by the backend, such as API credentials, must be supplied through the local environment rather than committed to Git.

---

## Production Considerations

The current API configuration is intended for development and integration with the new website.

Before production deployment, the following areas should be reviewed:

* CORS allowed origins;
* API authentication/security;
* environment configuration;
* backend hosting;
* frontend/backend URLs;
* error handling;
* logging;
* rate limiting;
* secret management.

These items should not be interpreted as missing core functionality; they represent deployment considerations for a production environment.
